## Brief 031 · Version at merge: merge in any order, no renumbering

Tooling, no rule, brain or screen change (rule set v3.10 stays the newest). The first version counted at merge.

**What the Editor will notice**
- Builds merge in the order they are ready. A pull request carries no version number, so merging one no longer forces a sync, a renumber and a second release run on the others.
- The number appears on the board and the live site after the merge (this build: one ZZ after v3.20.00). A preview's Home reads `<main's version>+NNN`, for example `v3.20.01+032`.
- A new required check, **waits-on**, blocks a build whose brief waits on one that hasn't merged, and turns green by itself when that one merges. It needs ticking once in Settings (see the Report).
- The 2,000-game release run happens only when a build changes a game file. A screen-only build gets none; its results line says "same games as" the last version that had one.
- The status board's Building line says what each build would be if merged next, and "waits on NNN" where it applies. "Needs sync" now means a real conflict only.
- The live site has the assembled changelog (`changelog.html`) with the version table.

**Under the hood**
- `board/version.js` holds `game: null, build: null`; an unstamped board shows `dev`. `tools/stamp-version.js` counts the number from `main`'s first-parent history after `releases/BASE.json` and stamps it into published copies only (blobless fetch; well under a second to count).
- Each brief adds `releases/NNN.json` and `changelog/NNN.md`. `tools/check-release.js` replaces `check-build-number.sh`. `tools/waits-on.js` and `.github/workflows/waits-on.yml` set the `waits-on` status.
- The lab plans the release from what changed (`sims/lab/release_files.js`); the release run's quick checks are built from `board/tests/test_*.js` (`sims/lab/release_tests.js`, replaces `release_quick.txt`), so the 13 test files the old list missed now run, the four browser checks included; its regression hashes cover every preset, the newest included.
- A docs-only pull request skips the game jobs; `checks` still reports.
