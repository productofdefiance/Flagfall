## Brief 031 · Version at merge: merge in any order, no renumbering

Tooling, no rule, brain or screen change (rule set v3.10 stays the newest). The first version counted at merge. Rebuilt after the red team's design review (the brief's Amendments).

**What the Editor will notice**
- Builds merge in the order they are ready. A pull request carries no version number; it appears on the board and the live site after the merge (this build: one ZZ after v3.20.00). A preview's Home reads `<version>+NNN`, the version being the last one the branch really contains.
- A new required check, **waits-on**, blocks a build until every brief it waits on has merged and is in the branch ("028 merged: sync once to test on it"). It also fails a malformed `Waits on` row, a brief that doesn't exist and a loop. Tick it once every open pull request shows it (see the Report).
- The 2,000-game release run happens only when what decides the games changes (the game files, the dice seeds or the lab's play scripts), or a build names new rules or a new default brain. On `main` every version gets its run or a "same games as" line, even when merges come close together.
- A fix to a merged brief has a place: `NNN-2`.
- If `main` fails its checks after a merge, a "Main broken" issue opens and the status board says "main broken since NNN".
- The status board's Building line says what each build would be if merged next, and "waits on NNN". "Needs sync" means a real conflict only.

**Under the hood**
- `board/version.js` holds `game: null, build: null`; an unstamped board shows `dev`, and the lab refuses to file results from it. `tools/stamp-version.js` counts from `releases/BASE.json` and fetches the history it needs itself.
- Each brief adds `releases/NNN.json` (its identity) and `changelog/NNN.md`. `tools/check-release.js` replaces `check-build-number.sh`. `tools/waits-on.js` posts the `waits-on` status on every open pull request (pull request events, every push to `main`, hourly).
- One generated test list: each test declares its counts in a `// @test` line, and `tools/run-tests.js` runs them for `checks`, the release run and night checks. 13 test files the old release list missed, `test_rematch.js`, `test_page.js` (run nowhere before) and the lab and status tests are now in every run where they belong; night checks pick up a new brain's test by themselves.
- The release decision uses a game key; the lab's plan job stamps once and passes the version to every later job. The default opponent moved from `app.js` to `brain.js`. A build's branch no longer carries the results index.
- The live site has the assembled changelog (`changelog.html`) with the version table.
