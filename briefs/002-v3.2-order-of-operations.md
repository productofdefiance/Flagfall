# Brief 002 — v3.2: order of operations

| | |
|---|---|
| Rule set | v3.2 (new preset, copied from v3.1) |
| Date | 17 Nov 2026 |
| Goal | Every exchange has an order of operations, so exactly one unit survives it, and no single action can end the match for both sides. |
| Branch | `build/002-v3.2-order-of-operations` |
| Flags | F3, F4, F5 |

## Context
The Editor's principle (ruled 17 Nov): a unit that dies can't strike back, so two units never trade fatal blows in one action. Today a Heavy Melee killed by an attack still parries, which can remove its attacker too. v3.1's fallback gives a double knockout to the side that acted. The Editor ruled that a double knockout should go to the turn-limit tiebreaks instead. In practice, once dead units can't parry, a double knockout should never happen. This build proves that.

## Scope
In: a new preset v3.2 with two switches, and tests. Out: everything else, including parry firing on the first attack only (locked 17 Nov, coming in a later brief) and any bot change.

## What to build
1. **New preset `v3.2`**, a copy of `v3.1`, added as the last entry in `PRESETS` so it becomes the new-game default. Note: "v3.1 plus: dead units don't parry; a double knockout goes to the tiebreaks."
2. **Switch `parryNeedsSurvivor`** (on in v3.2): parry fires only if the braced unit still has more than 0 HP after the hit. A unit removed by the hit deals no parry.
3. **Switch `doubleKoToTiebreak`** (on in v3.2; `simultaneousToActor` off in v3.2): if one action leaves both sides with a KO or TKO, the match is settled by the same order the turn limit uses: more pull damage, then fewer beings lost, then a draw. The result's `how` must make clear it came from a double knockout (for example `"double knockout, more pull damage"`).
4. **Tests** in a new `board/tests/test_v32.js`:
   - a braced Heavy Melee killed by an adjacent attack deals no parry on v3.2, and does deal it on v3.1 (fails before, passes after);
   - a braced Heavy Melee that survives still parries on v3.2;
   - a hand-built position where one action finishes both sides resolves by the tiebreaks on v3.2 (force it with set spear or a test-only state if parry can no longer cause it);
   - **double-knockout count:** 400 seeded bot games at 7v7 and 400 at 5v5 on v3.2 (Kit B vs Kit B, balanced lineups, `tests/rng.js`). Count actions after which both sides had a win condition. Expected: 0. Print the count; fail the test if it is above 0.

## Rules it touches
Parry (Heavy Melee's brace benefit); set spear (Heavy Anti-Cavalry); taking the hex after a kill; the flag pool (a parry on a holder goes into the pool); the turn-limit tiebreak order; the TKO definition.

## Must not change
match3, v1, v2, v3 and v3.1 play and replay identically (same `regress_engine.js` hashes). The v3.1 tests still pass.
